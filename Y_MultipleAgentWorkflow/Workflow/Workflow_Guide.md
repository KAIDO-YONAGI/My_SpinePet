# 多 Agent 工作流指南

## 1. 路由原则

先从根 Router 按任务名词、目标文件、运行资源和预期输出逐级匹配。任务描述
只用于定位，实际做法必须从被路由业务的 Guide/Design 中获取。跨业务任务
同时进入多个业务根，不能由一个 Router 替代另一个。

## 2. 业务根增殖

1. 在根索引查直接匹配。
2. 在最近大类 Router 查同义任务和下级分类。
3. 存在同类时复用现有文档与先验方法。
4. 不存在时，在最近大类下从模板创建业务根，至少包含 `Router.md` 和
   `DeveloperLog.md`。
5. 新增顶级大类、改变工作区通用规则或归属有争议时先询问用户。
6. 未实施方案命名或状态必须包含 `Proposal`，且不得写成已实现能力。

## 3. 五层上限

`Y_MultipleAgentWorkflow` 下的业务索引最多五层（不把文件本身计为一层）。
即将产生第六层时，按顺序考虑：

1. 把可独立演进的子类提升为新业务根。
2. 合并语义重复的上级与下级。
3. 用 Router 标签或表格代替只含单一文档的目录。

不得为了形式完整继续增加空壳目录。

## 4. Router 要求

每个业务 Router 至少记录：

- 文档 ID、状态、维护计数和最后更新时间。
- 任务线索到权威文档的路由。
- 下级业务根。
- 本业务共享资源名。
- Proposal 与 Active 能力的边界。

根 Router 文档索引还要记录路径、职责摘要、触发任务、状态、更新时间、
核验时间和旧路径。路径变化后同一次修改中更新索引。

## 5. 日志与计数

任务成功且实际影响业务时，在对应 DeveloperLog 写入：

```text
日期、任务摘要、关键文件/资源、验证证据、结论、维护计数变化
```

- 跨业务任务对每个受影响业务分别记一次。
- 失败、取消、并发登记、只读调查和纯文档维护不计数。
- 第五次完成后复查该周期日志与代码，更新 Guide/Design 和根路径索引。
- 无需修改时写 `reviewed-no-change`。
- 复查完成后把业务 Router 和根 Router 的计数重置为 `0/5`。

Router/Log 写入只在短临界区申请 `workflow:<业务根>`，不把业务任务全程
锁为冲突。

## 6. 未知任务

找不到同类业务时，Agent 可以完成轻量只读分类，但不能直接创建顶级大类。
先向用户说明最接近的大类、建议的新业务根和是否会改变工作区规则；确认后
再用模板初始化。
