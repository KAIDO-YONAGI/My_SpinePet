多 Agent 工作流与并发租约体系：最终设计基线

状态：Reference
基线日期：2026-08-21

本文件记录设计目标、最终实现和验证结果，不是运行时操作入口。发生冲突时，
以 `Y_MultipleAgentWorkflow\Router.md` 及其指向的 Guide/Design 为准。

## 1. 目标

建立受 Git 管理的 `Y_MultipleAgentWorkflow\`，作为 Codex、Claude、ZCode
共用的项目文档入口。Agent 根据任务只读取相关业务知识，并通过 WorkingAgent
租约在共享工作树中协调并发。

跨项目通用配置方法见：

`Y_MultipleAgentWorkflow\Workflow_Configuration_Guide.md`

## 3. 已验证的分类结论

一级根按稳定知识域划分：

- `Workflow`：工作流自身。
- `GUI`：界面和交互。
- `Resources`：资源生命周期。

二级按任务阶段或处理目标划分：

- `Resources.Load`：识别、入库、ID、图标和部署。
- `Resources.MatchClean`：附件匹配、清理和动画排查。
- `Resources.StateSupport`：aim/cover 等状态能力；未实施内容保持 Proposal。

分类不按模型、Agent、语言或文件类型。只有具备独立触发词、权威文档、并发
资源或维护周期时才增殖业务根。索引最多五层。

## 4. WorkingAgent 最终协议

Agent 可先轻量只读探索，但在详细分析、创建子 Agent、首次修改或启动会改变
状态的工具前必须取得租约。

租约文件名：

```text
<AgentName>_<Hash>.txt
```

Hash 使用 Agent 名、模型、会话 ID、UTC 启动时间和随机 nonce 的 SHA-256
前 12 位。JSON schemaVersion 为 1，保存租约 ID、所有者、任务类别、访问
模式、资源范围、状态、UTC 时间、冲突和覆盖批准记录。

接口：

```powershell
-Action Acquire
-Action Heartbeat
-Action UpdateScope
-Action Wait
-Action Release
-Action Status
```

扫描、写入和删除均在固定注册表锁的独占文件句柄下完成。普通更新和释放必须
同时匹配 `leaseId` 与 `sessionId`。

## 5. 实施后纠正

以下内容以真实测试修正了实施前假设：

1. `Wait` 在同一次注册表锁内重新检测并原子转为 `active`。
2. 等待循环每次按租约 ID 重新读取注册表，已释放的 waiting 记录不会被旧
   内存对象复活。
3. `startedAtUtc`、`heartbeatAtUtc` 和覆盖时间写盘、更新和输出均规范化为
   UTC ISO 8601。
4. 超过 15 分钟仅标记 `suspectedStale`，禁止自动删除或接管。
5. 路径父子关系视为相交；没有足够资源范围的同业务写任务默认冲突。
6. `UpdateScope` 在提交新范围前检测冲突；失败时保留旧范围。
7. Router/Log 使用短时 `workflow:<业务根>`，根结构使用 `workflow:root`。
8. `pipeline:BuildPublishRun` 与所有活动写/独占租约形成全局屏障。
9. 普通 `OverrideConflict` 不包含构建屏障，必须另行
   `ConfirmBuildBarrierOverride`。
10. PowerShell 数组应直接传入脚本或使用 `ProcessStartInfo.ArgumentList`，
    避免外层命令字符串把引号写进资源名。

## 6. 心跳、等待和覆盖

- 活动或等待 Agent 每 5 分钟、长操作前后和扩大范围时更新心跳。
- 非冲突的疑似失活记录只提示。
- 冲突时向用户报告所有者、任务、资源和最后心跳。
- 用户可以等待、在明确范围内覆盖、确认旧 Agent 已停止后清理，或停止当前
  任务。
- 等待默认每 60 秒检查，30 分钟未解除则返回超时并保留 waiting 标记。
- 任务完成、失败和取消都应在 finally 路径释放；崩溃遗留由后续任务识别。

## 7. 路由与维护

权威顺序：

用户最新要求 -> 实际代码/资源/实验 -> Guide/Design -> 业务 Router ->
DeveloperLog/Proposal -> 模型入口与 Skill。

没有同类业务时在最近大类下从模板初始化；新增顶级大类或工作区规则必须先
询问用户。每个实际影响业务且成功完成的任务计数 `+1`，第五次完成后复查
周期证据和实际代码；无需修改时记录 `reviewed-no-change` 后归零。

外部 nikkedb 文档保持原位，由根 Router 索引，不复制进工作流。

## 9. 验证结果

`Test-WorkingAgent.ps1` 真实子进程回归结果为 `12/12`，覆盖：

- 只读并行和不相交写并行。
- 同路径、父子路径、共享资源与隐式范围冲突。
- 两进程同时 Acquire 仅一个成功。
- 心跳、15 分钟疑似失活、禁止自动删除和确认清理。
- 等待后原子取得租约。
- 用户覆盖及冲突记录。
- 扩大范围发现新冲突且保留旧范围。
- Router/Log 短临界区。
- Build/Publish/Run 独立确认屏障。
- 租约所有权。
- 异常退出标记可发现。

路由演练覆盖 GUI、资源导入、清理、Aim/Cover、跨业务、未知业务、第五次
维护和超过五层，全部符合规则。迁移后旧操作路径和旧文件名引用仅允许作为
索引中的旧路径元数据。

首次完整收尾验证：Build 0 警告 0 错误，Publish 成功生成 release 与 zip，
Run 后 `SpinePet.exe` 持续运行。

## 10. 已知环境事项

执行首次 Run 的 Codex 子进程环境中 `WINDIR` 为空，WPF FontCache 因此抛出
URI 格式异常。仅对 Run 子进程设置：

```powershell
$env:WINDIR = $env:SystemRoot
```

后验证成功。该问题属于调用进程环境，不是 SpinePet 代码、工作流协议或需要
永久修改的系统配置。

## 11. 跨项目 Skill

通用 Skill 名称为 `multiple-agent-workflow-config`。唯一实体位于：

`C:\Users\12248\.agents\skills\multiple-agent-workflow-config`

Claude 与 ZCode 通过目录 Junction 共用该实体。Skill 提供分类分析、用户
确认、工作流初始化、自包含 WorkingAgent 复制和结构校验。模型入口默认不
修改，必须先让用户选择“保留并加入导航”或“替换为精简入口”。
